# utils 安全编码规范

本文件只维护 `utils` 公共包安全规则。AI 新增或修改认证、上下文、AOP、异常、响应、SQL 校验、文件、脱敏、上传下载、日志或第三方 SDK 封装时，必须先阅读本文件。

## 接口鉴权和认证上下文

- `utils` 可以提供认证过滤器、用户上下文、权限表达式和公共注解，但不得恢复旧 token 请求头或 Redis token 用户对象认证模式。
- 公共认证能力必须以 `SecurityUser`、`UserContextHolder` 和标准 Spring Security 上下文为边界，业务服务负责具体权限码和资源授权。
- 请求结束、异常结束、退出登录、用户禁用、密码变更、刷新 token 失败等场景必须清理用户上下文、租户上下文、动态数据源上下文、幂等锁和可能的 token 缓存。
- 退出清理 token 是公共认证能力的强制要求，公共包不得提供让旧 token 在退出后继续访问接口的兼容逻辑。
- 认证失败、权限失败和 token 解析失败只返回稳定错误码和必要提示，不向调用方暴露密钥、算法细节、堆栈或内部类名。
- 公共认证组件必须支持频率限制、失败次数限制、验证码、token 过期、token 撤销和安全审计扩展点，避免业务服务重复造安全逻辑。
- 如果公共包支持 Cookie、浏览器自动携带凭证或表单提交模式，必须提供 CSRF 风险说明和 SameSite、CSRF Token、Origin/Referer 校验扩展点。

## 水平越权和租户隔离

- 公共查询、拦截器、AOP、MyBatis-Plus 插件和上下文工具必须默认支持租户隔离，不得信任前端传入的 `tenantId`、`userId`、`role`、`permission` 作为授权事实。
- 数据权限公共能力必须防止水平越权；业务服务替换 `id`、`tenantId`、`ownerUserId`、`deptId` 时，公共能力要提供可复用的校验入口或插件能力。
- 批量操作、导入、导出和授权绑定的公共工具必须支持逐条校验，不得只校验入口对象后默认信任整个列表。
- 线程池、异步任务和 Feign 调用必须明确上下文传递和清理规则，防止线程复用导致用户、租户或数据源串号。
- 公共转换、复制、映射工具不得默认把请求对象的全部字段写入 Entity，必须支持写入字段白名单，防止批量赋值覆盖 `tenantId`、`roleId`、`state`、`isDelete`、`version` 等敏感字段。
- 公共序列化和 VO 组装能力必须支持字段级授权和脱敏扩展，避免业务服务通过列表、详情、导出等接口泄露对象属性。

## SQL 注入和参数校验

- SQL 参数校验能力必须覆盖 `select`、`insert`、`update`、`delete`、`drop`、`truncate`、注释符、联合查询、堆叠语句等高危片段。
- 公共 SQL 工具必须优先使用参数绑定、MyBatis-Plus Wrapper 或 LambdaWrapper，不提供直接拼接用户输入的便捷方法。
- 排序字段、动态表名、动态列名、导出字段和搜索字段必须使用后端白名单，不允许把请求参数直接拼接为 SQL 片段。
- XML Mapper 中 `${}` 只能接收后端白名单值；公共规范和示例必须引导业务代码使用 `#{}` 参数绑定。
- 公共分页、导出、搜索和批量查询能力必须限制 `pageSize`、导出条数、时间跨度、关键字长度和批量 ID 数量，防止无限制资源消耗。

## MyBatis-Plus 官方 SQL 安全能力

- MyBatis-Plus `SqlInjector` 只是自定义通用 Mapper 方法的注入机制，用于扩展 SQL 方法，不是防 SQL 注入工具。
- 新增或修改 `SqlInjector`、`AbstractMethod`、自定义批量插入、批量更新、批量删除方法时，只能使用实体元数据、框架字段信息、后端常量和白名单值生成 SQL。
- 动态排序、动态 select 字段、动态表名、导出字段和搜索字段必须以服务端白名单为主防线，禁止把前端字段原样拼入 SQL。
- `SqlInjectionUtils.check(...)` 可用于手动校验前端传入的字段片段，但只能作为白名单之后的补充防护。
- MyBatis-Plus Wrapper 的 `checkSqlInjection()` 可用于自动检查动态字段片段，但覆盖范围不是完整安全边界，不能替代白名单。
- `IllegalSQLInnerInterceptor` 必须默认开启，用于拦截高风险 SQL、全表操作、索引风险和复杂危险条件。
- `BlockAttackInnerInterceptor` 必须默认开启，用于阻止没有条件的全表 `update` 和 `delete`。
- `DataPermissionInterceptor` 只负责数据范围 SQL 条件拼接，不能替代接口权限、租户隔离、资源归属校验和字段级授权。
- `TenantLineInnerInterceptor` 只负责 SQL 层租户条件拼接，租户 ID 必须来自可信认证上下文或网关上下文。
- Mapper XML 如必须使用 `${}`，参数来源必须是后端枚举、固定常量或字段白名单，且要配套 SQL 注入测试。
- MyBatis-Plus 安全插件被业务配置关闭时，必须在配置说明中写清关闭原因、替代防护、影响 SQL 范围和回归测试命令。

## SSRF 和外部请求

- 公共 HTTP、Feign、OkHttp、文件抓取、图片处理、Webhook 和第三方 SDK 工具如果接收 URL，必须提供协议、域名、端口、IP 段和重定向后最终地址白名单校验能力。
- 禁止公共工具默认允许访问内网地址、本机地址、云元数据地址、Nacos、Redis、MySQL、Actuator、Seata、网关管理端等内部资源。
- 外部请求工具必须默认设置连接超时、读取超时、最大响应体、重定向限制和失败降级，不得提供无超时的便捷方法。

## 数据脱敏和日志

- 公共响应、异常处理、日志切面、审计工具和消息通知工具不得输出密码、token、密钥、验证码、完整身份证、完整手机号、完整邮箱、数据库连接串、内部地址和异常堆栈。
- 数据脱敏能力必须能在 VO 组装、序列化、日志输出、导出下载、消息推送和审计记录场景复用，不能只依赖前端隐藏字段。
- 公共异常处理只返回稳定错误码、简短错误信息和必要追踪标识，不返回 SQL、服务器路径、内部类名或配置值。
- 新增日志字段时必须先判断是否包含个人信息、认证凭证或基础设施地址，默认只记录 ID、状态、耗时、租户和追踪字段。

## 加密、密钥和敏感配置

- 公共加密、签名、摘要、密码处理、验证码和随机数工具必须使用 JDK 或成熟库的安全实现，不得手写加密算法或使用可预测随机数。
- 密码哈希必须使用安全算法和随机盐，不得提供 MD5、SHA1、可逆加密保存密码的便捷方法。
- token、验证码、临时授权码、重置密码链接必须支持过期时间、一次性或可撤销能力，并且不能出现在日志、URL 查询串或异常信息中。
- 密钥、数据库密码、AccessKey、JWT Secret、短信签名密钥等敏感配置必须来自 Nacos、环境变量或密钥管理系统，不得写入代码、README 示例真实值或测试数据。

## 文件遍历和上传校验

- 文件读取、导入、导出、下载、压缩、解压和模板处理工具必须防止路径遍历；用户输入只能作为文件名，不得直接参与目录拼接。
- 拼接路径后必须使用 Java 标准路径规范化能力校验结果仍在允许目录内，禁止 `../`、绝对路径、软链接逃逸和 Windows 盘符逃逸。
- 文件上传公共能力必须校验大小、扩展名、MIME 类型和实际文件头；禁止上传脚本、可执行文件、HTML、SVG 等可能导致执行或 XSS 的内容。
- 文件名必须由服务端重新生成，原始文件名只能作为展示字段保存，并且展示前必须转义或脱敏。
- 解压工具必须防止 Zip Slip、压缩炸弹、超大文件、空文件、重复文件名覆盖和目录逃逸。

## XSS 跨站脚本

- 公共富文本、Markdown、消息、公告、模板、文件名和错误提示工具必须默认按纯文本处理，只有明确业务需要时才允许 HTML。
- 允许 HTML 时必须提供白名单清洗能力或明确要求业务侧清洗，禁止把未清洗输入拼接进 HTML、JavaScript、URL、HTTP 响应头或下载文件名。
- JSON 响应、错误响应和统一返回对象不得携带可执行脚本片段；前端展示字段必须保持可转义语义。
- 第三方通知、钉钉 Markdown、邮件、短信和站内信工具必须防止把未校验变量作为脚本、链接或 HTML 执行。

## 第三方 SDK 和基础设施

- Redis、OSS、短信、邮件、钉钉、Feign、RabbitMQ、Seata、Elasticsearch 等公共封装不得在日志或异常中输出密钥、token、签名、连接串和内部地址。
- 文件上传到 OSS 或其他对象存储前仍必须完成文件类型、大小、文件头和访问权限校验，不能把对象存储当成安全边界。
- Feign 请求头透传只允许认证、租户、链路追踪和业务必需字段，不得伪造用户、角色、权限等身份事实。
- Redis token、验证码、幂等锁、限流 key 必须设置过期时间，退出登录或认证状态变更时必须清理相关缓存。

## 安全配置和供应链

- 公共自动配置必须遵循最小暴露原则，Actuator、Knife4j、错误详情、静态资源、上传大小、请求体大小等能力不得在生产环境默认开放高风险入口。
- 新增依赖、插件、镜像、脚本和 Gradle/Maven 仓库时必须说明用途，优先使用可信仓库和稳定版本，避免引入未维护、漏洞严重或来源不明的组件。
- 依赖升级必须关注安全公告和破坏性变更，不得为了追最新版本跨大版本引入不兼容风险。
- CI/CD、发布脚本、初始化数据和配置变更必须保持可审计、可回滚，不能在构建脚本中明文写入密钥。

## 异常处理、完整性和反序列化

- 异常处理必须失败关闭，权限、租户、签名、验证码、token 校验异常不得降级为允许访问。
- 不得提供反序列化不可信 Java 对象、脚本、表达式、模板或规则的公共工具；确需动态表达式时必须限制变量、函数、执行时间和可访问类型。
- 回调、Webhook、支付通知、第三方事件、导入数据必须校验签名、时间戳、幂等键和数据完整性，不能只按请求来源 IP 或参数存在判断可信。
- 公共幂等、防重复提交和乐观锁能力必须在异常路径释放资源并保留审计证据，避免重放请求和异常失败开放。

## 安全日志、告警和审计

- 公共日志、AOP、异常处理和审计能力必须支持记录登录失败、权限拒绝、跨租户访问、越权访问、token 失效、敏感数据导出、批量操作、异常上传、SQL 注入和 XSS payload 命中。
- 安全日志必须包含时间、租户、用户、接口、目标资源、结果、原因和 traceId，但不得包含敏感明文。
- 高风险安全事件必须具备告警扩展点或可检索标识，不能只写普通业务日志后无人关注。

## 测试要求

- 修改认证、权限、上下文、AOP、SQL 校验、文件、上传、脱敏、异常和日志能力时，必须补充安全测试或最小复现验证。
- 认证测试必须覆盖未登录、token 无效、退出登录后旧 token、密码变更或用户禁用后的 token 失效。
- 数据权限测试必须覆盖跨租户、替换他人 `id`、批量列表混入无权数据和异步线程上下文清理。
- SQL 安全测试必须覆盖排序字段白名单、SQL 注入 payload、超长关键字、非法时间范围和 `${}` 风险场景。
- 文件安全测试必须覆盖非法扩展名、伪造 MIME、伪造文件头、路径穿越文件名、超限大小、空文件和 Zip Slip。
- XSS 测试必须覆盖 HTML、SVG、Markdown 链接、文件名、错误提示和富文本字段中的脚本 payload。
- 安全测试还必须覆盖 CSRF、SSRF、限流、批量赋值、字段级越权、异常失败关闭、敏感配置泄露、依赖风险、反序列化和安全日志审计。
