# 个人项目迁移整体验证

## 目标与范围

对个人 workspace 的 11 个 Java 项目和 `admin-web` 验证配置、制品、数据库、网关及实际接口；仅将通用能力迁入个人环境，医疗业务、患者数据和公司私有配置不属于迁移目标。移动端不纳入 workspace。

验收要求是前端实际请求能够到达正确服务、配置和数据相互匹配、公共包不会混用公司坐标，并保留必要的拒绝路径。源码提交、远端制品、CI 和运行验收分别取证。

## 发现的问题与处理

| 问题 | 证据与处理 |
|---|---|
| 登录响应重复 CORS | 网关和后端各加一组标头。gateway 已在响应合并边界过滤后端 CORS，保留网关 Origin 白名单；真实 HTTP 回归覆盖重复标头。 |
| 登录缺少账号和租户不一致 | 初始选择为干净初始化，不含人员账号；后续已按明确授权同步通用租户、管理用户及角色权限关系，未同步消费者、患者或其他业务数据。 |
| RAG 请求 404 | 公司 `/rag/**` 配有路径重写；个人网关直接接收 `/api/rag/**`，前端仍添加 `/rag`。个人前端已与个人路由对齐，7 个 service 契约测试修复前全部失败、修复后通过。 |
| 验证脚本及规范过时 | 实际三个 profile 已统一 `github-dev`，脚本和文档仍要求另外两个 namespace。统一现行约定，新增跨仓路径检查和 6 个路由反例测试。 |
| 部分长期分支落后 | 7 个后端的 `test/preprod` 少了 main 上的启动类更名或 Nacos 修正，确认无分歧后已快转补齐。 |
| ES 日志索引没有环境隔离 | 个人公共包仍固定使用共享 `request_log`。`com:utils:1.5.2` 支持 `elasticsearch.request-log-index`，个人 Nacos 使用 `github_dev_request_log`；未指定时保留原默认值，历史索引不迁移、不删除。 |

## 复验入口

```bash
python3 ops/github-dev/scripts/verify_configuration.py
python3 -m unittest discover -s ops/github-dev/tests -v
python3 ops/github-dev/scripts/sync_nacos.py
./gradlew test --no-daemon
bash scripts/check-secrets.sh
```

跨仓检查需要同级服务与 admin-web；路由反例测试已接入 utils CI，不需要同级源码。检查器覆盖当前 Path/StripPrefix 契约和 Controller 根路径，出现未支持的路径重写会拒绝给出通过结论；它不替代 HTTP 方法、参数、权限和在线接口验收。私有在线脚本与原始回执不进入公开仓库。

## 版本、回滚与验收边界

- utils `1.5.1 → 1.5.2`；7 个消费者各递增一次补丁版本并固定新依赖。rpc-api 维持 `1.0.7`，纯文档修改的项目不升版本。
- 回滚 ES 隔离时必须同时评估消费者版本与 Nacos 索引配置，避免旧包忽略新键后重新写入共享索引；回滚不删除任一索引。历史日志不会自动迁移。
- 整体 ES 集群的 yellow 来自单节点上旧 `request_log` 的一个未分配副本，所有主分片正常。个人新索引为单主分片、零副本。此次没有改公司/旧索引副本策略，也没有关闭 ES 健康检查。
- Java 默认套件中的 MinIO 用例已另行显式验收；AgentCard 真环境注册测试仍跳过，因为个人环境按原约定关闭自动发布。message 的 `manual-rpc` 标签不属于默认测试套件，本轮未另外启用。
- 付费模型推理、RAG 文档导入后的 embedding/检索效果、完整 Agent/RPC 编排、微信/移动端及浏览器逐页点击不属于已完成的在线验收，不能由健康检查、路径测试或构建通过推定完成。
- 公司医疗模块和对应表未整体复制是范围约定；个人代码仍引用的空表保留结构。初始化脚本仍不创建默认人员账号，现有开发库的授权管理账户同步不会变成公开种子。
- 新版本远端制品、各仓最终分支 SHA 和 CI 以发布回执及实际远端为准；本文件记录检查范围与方法，不替代实时状态。
